## 1. Цель
Собрать **кликабельный статик-превью** сценария «Готовые проекты + Построенные объекты» — задизайненные страницы
на **реальных намайненных данных** (163 дома + 40 объектов + галереи/планы), БЕЗ бэкенда/CMS/БД/логики сервера.
Назначение — заказчик проходит превью и утверждает вид/состав блоков/потоки. Де-риск: правки по дизайну здесь
дёшевы (только вёрстка), пока не вложились в бэкенд.

pnpm-workspace (или добавить в workspace — на усмотрение). Это «директория превью» из постановки.

## 4. Экраны (из WIREFRAMES — распараллеливается по экранам)
1. **TopBar / шапка** — лого, город, 8-800 + телефон, кнопки **Telegram/WhatsApp**, CTA «Подобрать/Рассчитать».
2. **Главная** — конверсионный первый экран (крупный оффер + CTA), тизер каталога, trust-счётчики
   («построено N домов», лет на рынке), блок «построен N раз», нарратив «сопровождаем от чертежа до заселения».
3. **Каталог `/projects`** — сетка карточек (фото/цена «от»/бейджи/площадь·спальни·этажи) + **фильтры Primary**
   (технология · площадь · цена · этажность · спальни · стиль; вторичные под «ещё») + сортировка (вкл. «по популярности»);
   всегда виден счётчик результата.
4. **Карточка проекта `/projects/[slug]`** — галерея+лайтбокс, spec-панель, **inline-переключатель материала
   «построить из»** (клик по газобетон/кирпич/СИП → меняются цена «под ключ от» и пакеты — на клиенте, по фикстуре),
   планировки в табах этажей, комплектации Базовая/Стандарт/Комфорт, sticky-CTA + мессенджеры.
5. **`/works`** — карта-заглушка (статичные пины или картинка) + сетка построенных объектов со счётчиком «N фото».
6. **Деталь объекта `/works/[slug]`** — фотохроника (галерея), параметры, статус, связь «Построен по проекту →
   Хочу такой дом» (ведёт на карточку проекта).
7. **Квиз «Подбор»** — 5-6 шагов (назначение/площадь/бюджет/этажность/спальни/материал) → показать **3-5 подходящих
   проектов + вилку цены** → форма-заглушка захвата лида. Матчинг — на клиенте по фикстуре.

## 5. Ограничения Фазы S
- **Статик:** без API/CMS/БД/Prisma/реальной отправки форм. Формы/кнопки лидов — заглушки («Заявка принята» / «превью»).
- Клиентская интерактивность (переключатель материала, фильтры, квиз-матчинг, лайтбокс) — **это ОК**, это не бэкенд-логика.
- Карта — статичная заглушка (Leaflet можно и позже; для превью хватит картинки/простых пинов).
- Никакого MinIO/загрузки — картинки хотлинком по URL из данных.

## 6. Технически
- **Next.js (App Router)** как в `apps/ncottage-www` (Next 15) + **Tailwind** для быстрой аккуратной стилизации.
  Это витрина для заказчика — **выглядеть должно как дизайн, не как сырьё** (типографика, отступы, hover, адаптив).
- Скопировать `projects.normalized.json` + `built-objects.normalized.json` в `preview/fixtures/`, читать из них.
- Зависимости ставить свободно (полный аппрув). Деплой — превью-ссылка (`next build` → static export или `next start`).

## 7. Готово (DoD)
- Все 7 поверхностей кликабельны и связаны (каталог → карточка → квиз → /works → объект → назад).
- Наполнено **реальными данными** (не lorem): 163 дома в каталоге, 40 объектов, настоящие цены/фото/планы/пакеты.
- Desktop + mobile.
- Заказчик проходит полный сценарий; **переключатель материала** и **квиз** реально работают на клиенте.
- Развёрнуто как ссылка для заказчика.

## 8. Форма данных (для фикстур)
```
projects.normalized.json[]: {
  slug, name, dimensions("7x9"), area, bedrooms, bathrooms, floors("1"|"1.5"|"2"|"mansard"),
  categories[], technologies[]("frame"/"gas_concrete"/…), features[]("terrace"…), description,
  renders[url],                       // фото-галерея (рендеры)
  floorPlans[{floor("1 этаж"|…), url}],
  variants[{ technology, priceFrom, priceLow, priceHigh, packages[{name("Базовая"…), price}], mortgageFrom }]
}
built-objects.normalized.json[]: { title, slug, technology, location, status("built"|"in-progress"), floors, gallery[url] }
```
Примеры технологий→подписи и стилей — по §Г ТЗ; цена «от» дома = min по `variants[].priceFrom`.

WP0+ (модель/CMS/API) — это после утверждения превью. Планы этажей есть не у всех домов (63%) — где нет, секцию скрывать.
