# EPIC: сквозной QA-аудит ncottage CMS

Kickoff-промт для отдельной сессии. Цель — не доработка фич, а **выявление дефектов,
несоответствий и точек оптимизации** по всему продукту (www + admin + api), сборка
приоритизированного **досье находок**, и после триажа с владельцем — починка порциями.
Эталона-Figma нет: дизайн оценивается на **самосогласованность** (консистентность
дизайн-системы, UX-качество, адаптив, доступность); продуктовые требования = `SPEC.md`.

Репозиторий `~/Documents/forge` — **git + GitHub**, НЕ Arc. Ветка `feat/ncottage-cms`.
Обычные `Read/Grep/Glob` безопасны (это git, не arcadia).

## Ориентация (прочесть в этом порядке)

1. Память: `project_ncottage_cms` (полный прогресс A–G, E0–E5, F; паттерны Page+PageSection,
   коллекций, settings; gotchas), `feedback_forge_workflow` (git-конвенции),
   `feedback_verify_scope_claims` (верифицировать находки в обе стороны — критично для аудита),
   `feedback_doc_writing`, `arc_vfs_repair`/раздел про colima (среда).
2. `docs/ncottage-cms/{SPEC.md, CONTENT-MODEL.md, ROADMAP.md}` — источник продуктовых требований
   и карта сущностей.
3. `git log --oneline -8` — свериться. Рабочее дерево должно быть чистым на старте.

## Что уже сделано (контекст, не переаудит фич ради фич)

Эпики A–G, E0–E5, F реализованы и верифицированы. Весь контент сайта управляется из админки
(turnkey). Миграция контента была **pixel-preserving** — www рендерит то же, что статичный
оригинал. SEO-метаданные, sitemap.xml, robots.txt, Open Graph — из API (эпик F). RBAC: admin/editor,
delete только admin. Лиды: Telegram + email под конфиг-флагами. ISR: on-demand revalidate по тегам.

Аудит НЕ должен ломать pixel-паритет там, где он намеренный, и НЕ переоткрывать решения D1–D7.

## Принципы аудита

- **Audit-first.** Сначала полное досье находок по всем измерениям, потом триаж с владельцем
  (fix-now / backlog / wontfix), и только затем починка. НЕ чинить массово без триажа — полный QA
  легко даёт десятки находок, не все стоит править сейчас.
- **Состязательная верификация каждой находки.** Урок эпика F: дискавери-агент пометил 6 ISR-тегов
  как «мисматч» — все оказались ложными (per-slug теги избыточны у list-only коллекций). КАЖДУЮ
  находку проверять в обе стороны и репродуцировать (скриншот / curl / repro-шаги) ДО внесения в
  досье. Severity без доказательства не ставить.
- **Дефект vs вкусовщина.** Различать объективный дефект (баг, нарушение WCAG, несогласованность
  с дизайн-системой, расхождение со SPEC) и субъективное предпочтение. Предпочтения — отдельной
  пометкой, не как баги.
- **Самосогласованность как эталон.** Без Figma «несоответствие дизайну» = отклонение от паттернов,
  которые сам проект использует в 90% случаев (один и тот же отступ/типошкала/вариант компонента
  в одном месте и иной в другом — находка; единый осознанный стиль — не находка).
- **Конкретность.** Каждая находка: где (file:line / route / breakpoint), что не так, доказательство,
  рекомендация, оценка трудозатрат.

## Измерения и критерии

### A. www — дизайн / UX / адаптив
Метод: реальный браузер (Playwright + chromium, уже установлен в `apps/ncottage-www`), скриншоты
на брейкпоинтах 390 / 768 / 1280 / 1440, обход всех публичных роутов (список — из дискавери; ~30
страниц + детальные по слагам).
- Консистентность дизайн-системы: spacing/типошкала/цвет-токены/радиусы/тени — единообразны? Поиск
  ad-hoc стилей, магических чисел в CSS-модулях, дублирующих вариантов кнопок/карточек/заголовков
  мимо общих примитивов (`components/ui/*`).
- Адаптив: на каждом брейкпоинте — горизонтальный скролл, переполнение, наложения, обрезанный текст,
  тач-таргеты < 44px, нечитаемые размеры, ломающиеся сетки/таблицы/карусели.
- Состояния: hover/focus/active, пустые (нет проектов/отзывов/в избранном/сравнении), ошибки (форма,
  API down), загрузка/скелетоны, успех отправки лида. Каждое состояние реально вызвать.
- Микрокопирайтинг: опечатки, рассинхрон тона, забытые плейсхолдеры, висячие предлоги, обрезка.
- Взаимодействие: клавиатурная навигация, фокус-ловушки в диалогах/модалках, поведение каруселей,
  dnd, плавающих CTA. Консоль без ошибок (кроме известного безобидного dnd hydration в админке).
- Кросс-страничная согласованность: header/footer/breadcrumbs/CTA-паттерны/формы.

### B. www — производительность / SEO / a11y
- Core Web Vitals: LCP, CLS, INP. Картинки (`next/image`: `sizes`, `priority` на LCP-картинке,
  форматы, отсутствие layout shift), шрифты (уже `display:swap`), размер бандла по роутам,
  code-splitting, мёртвый JS/CSS. Инструмент Lighthouse — **не установлен**, предложить установку
  (`lighthouse` CLI или `@lhci/cli`) и подтвердить у владельца перед `pnpm add`.
- ISR/кеш: повторно подтвердить теги revalidate (в F аудировано — свериться, не дублировать ложные
  «мисматчи» по per-slug у list-only коллекций).
- SEO-техника: иерархия заголовков (ровно один h1 на страницу), alt у изображений, JSON-LD
  (есть FAQ/Article — проверить валидность и полноту, добавить Organization/BreadcrumbList где
  уместно), внутренняя перелинковка, canonical/OG (в F сделано — спот-чек), 404/мягкие notFound.
- a11y (WCAG 2.1 AA): контраст, alt, aria-labels, label у полей форм, видимый фокус, семантический
  HTML, landmark-регионы, операбельность с клавиатуры, порядок чтения скринридером. Инструмент
  `@axe-core/playwright` — **не установлен**, предложить + подтвердить установку.

### C. admin — UX редактора
Метод: авторизованный браузер (cookie-рецепт ниже), обход всех разделов и форм.
- Полнота turnkey: реально ли отредактировать ВЕСЬ контент? Свериться форма-за-формой с контрактами
  (`@forge/shared`) и `CONTENT-MODEL.md` — нет ли поля в контракте, которого нет в форме; нет ли
  контента на сайте, не покрытого админкой.
- UX форм: сообщения валидации, индикаторы обязательности, фидбэк сохранения (тосты), обработка
  ошибок API (400/401/500 на экране, не в консоль), pending-состояния, предупреждение о несохранённых
  изменениях, подсказки к полям, UX репитеров и MediaPicker, навигация после сохранения.
- Консистентность: единый layout форм, русские лейблы/термины, иконки разделов.
- RBAC глазами editor: видит только разрешённое, кнопки delete скрыты, нет мёртвых ссылок,
  `/users` недоступен.
- Пустые/ошибочные состояния: пустой список, API недоступен, потеря данных при save-roundtrip
  (сабмит→GET, данные байт-в-байт через конвертеры, key-order-insensitive).

### D. api / данные — корректность
- Контракты: каждый мутирующий эндпоинт валидирован (DTO class-validator / zod settings),
  `forbidNonWhitelisted`, единые формы ошибок (400/401/403/404). Нет необработанных кейсов.
- Целостность данных: cascade-удаления, мягкие ссылки (`relatedSlugs`/`relatedObjectIds` на
  несуществующие слаги — поведение www при битой ссылке), форма JSONB, стабильность порядка
  (`order`/`createdAt` — re-seed не ломает; gotcha reviews).
- ISR: каждая мутация шлёт revalidate, www-фетчи помечены теми же тегами (свериться с F).
- Лиды: доставка под флагами, `deliveryError`/`deliveryAttempts`, `/leads/:id/redeliver`,
  поведение без кредов (логируется + помечается delivered).
- Безопасность: авторизация на всех мутациях, enforcement RBAC, валидация/санитизация входа,
  отсутствие инъекций (в т.ч. в метаданные `<head>`), обращение с секретами/токенами, CORS.
- Краевые случаи: пустые коллекции, отсутствующие опц. поля, крупный/невалидный вход, гонки
  правок (`nest --watch` races — для чистого e2e kill+single start).

## Как разворачивается

1. **Дискавери (Workflow, параллельные ридеры).** Инвентаризация поверхности аудита: все www-роуты
   (+ ключевые компоненты/состояния), все admin-разделы/формы, все api-эндпоинты/контракты, матрица
   брейкпоинтов. Репо маленькое, обычный Read/Grep безопасен. Результат — структурированная карта,
   по которой нарезаются аудиты.
2. **Аудиты по измерениям (Workflow).** По агенту (или пулу) на измерение A/B/C/D, каждый
   прогоняет свой чеклист, отдаёт находки структурой `{title, dimension, severity, type, surface,
   evidence, recommendation, effort}`. Визуальные/адаптив/a11y агенты используют Playwright
   (скриншоты/axe); perf — Lighthouse; admin — авторизованный браузер; api — curl живого API.
3. **Состязательная верификация (Workflow).** Каждая находка проходит скептика(ов): репродуцируется
   или опровергается. `isReal=false` по умолчанию, пока не доказано. Перспективно-разные линзы для
   находок с несколькими режимами отказа.
4. **Досье находок.** Дедуп, приоритизация (severity × effort), категоризация (bug / design-inconsistency
   / perf / a11y / sec / optimization / preference). Формат записи — ниже.
5. **Триаж с владельцем.** Показать досье, получить разбивку fix-now / backlog / wontfix. НЕ чинить
   до триажа.
6. **Починка порциями + верификация.** Согласованные находки — порциями (backend → admin → www),
   ветка зелёная (`pnpm -r typecheck`, `pnpm lint`, `pnpm -r build`), каждая правка доказательно
   проверена (повторный скриншот/repro/e2e). Не ломать pixel-паритет там, где он намеренный.
7. **PR.** Решает владелец: один общий PR или отдельный QA-PR. НЕ пушить без явного «да».

## Формат записи в досье

```
[ID] severity(critical/high/medium/low) · dimension(A/B/C/D) · type
Поверхность: route / file:line / breakpoint / endpoint
Что не так: <конкретно>
Доказательство: <скриншот-путь / repro-шаги / curl / лог>
Рекомендация: <как чинить>
Трудозатраты: <S/M/L>
Статус триажа: <fix-now / backlog / wontfix> (заполняет владелец)
```

## Инструменты

- **Playwright + chromium** — установлен в `apps/ncottage-www` (`@playwright/test`, `test:e2e`).
  Скриншоты на брейкпоинтах, обход роутов, a11y-инъекции, проверки консоли.
- **Авторизованный admin** (рецепт): логин в API за JWT → `context.addCookies([{name:"admin_token",
  value:token, domain:"localhost", path:"/", secure:false}])` → goto/скриншот. www-страницы публичные —
  без cookie. Server-action PUT'ы server→server (невидимы в network) — проверять success-тост, не ответ.
- **a11y** — `@axe-core/playwright` НЕ установлен → предложить + подтвердить у владельца.
- **perf** — `lighthouse`/`@lhci/cli` НЕ установлен → предложить + подтвердить. Альтернатива без
  установки: ручной разбор бандлов из `next build` output + DevTools-метрики.
- Временные скрипты (скриншоты/e2e) класть в `apps/ncottage-www` и удалять после.

## Gotchas (перенести из эпиков)

- forge = git+GitHub. Conventional commits, заглавная буква, **БЕЗ упоминания агента/Claude** нигде.
- НЕ запускать `pnpm -r build` пока подняты `next dev` (затирает `.next`). Аудит/скриншоты — на dev;
  build — отдельно, dev погашены.
- НЕ запускать `next dev` И `next start` для одного приложения одновременно (ChunkLoadError).
- Среда: colima/Postgres может отвалиться (`PrismaClientInitializationError`, docker daemon down) →
  www→API 500 каскадом. Лечится `colima restart` + `docker-compose -f apps/ncottage-api/docker-compose.yml
  up -d`; API переподключается без рестарта.
- Next 15/React 19 стримит `<title>`/мета в тело — при парсинге head искать по всему HTML, не по
  срезу до `</head>`.
- `/tmp` в сессии может чиститься — временные скрипты держать в репо-папке или пересоздавать.
- Известный безобидный шум: dnd-kit hydration mismatch в админке; 4 преэкзистинг warning в
  `nc_presentation` (не трогать).
- ISR: per-slug теги у list-only коллекций (vacancies/faq/certificates/partners/built-objects/reviews)
  избыточны и НЕ являются багом — не репортить повторно.

## Инфра (локально)

- БД: `docker-compose -f apps/ncottage-api/docker-compose.yml up -d` (НЕ `docker compose`; при
  «Cannot connect» → `colima restart`). API: `pnpm --filter @forge/ncottage-api dev` (:3002).
  www `:3000`, admin `:3003`. Сид: `pnpm --filter @forge/ncottage-api db:seed`.
- Креды админки: `admin@ncottage.local` / `admin12345`.
- www нужен `NCOTTAGE_API_URL=http://localhost:3002` (есть в `.env`), иначе отдаёт fallback-статику.

## Режим работы

Audit-first: досье → триаж → порционные правки → верификация → PR владельцем. Состязательно
верифицировать находки (урок ISR-ложняка). Держать ветку зелёной. Спрашивать владельца перед
установкой зависимостей и перед push.
