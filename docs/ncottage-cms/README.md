## Источник истины по темам (исполнителю читать первым)

Реализуя тему, **обязательно** сверься с её **каноническим** доком — остальные доки её НЕ дублируют, а
ссылаются на него (чтобы описания не расходились). Пример: prisma-модель кода берётся из PRISMA-DRAFT, а
НЕ из пересказа в ТЗ.

| Тема | Канонический док | Что именно там |
|---|---|---|
| Схема БД, prisma-модель, типы, миграции, byte-identity | **[PRISMA-DRAFT.md](PRISMA-DRAFT.md)** | §1.1–1.9 модели, §1.10 материал-варианты + Taxonomy, §1.11 Setting/Quiz/SlugRedirect, §3 миграции, §4 shared |
| Модель-**обзор**, поля↔контролы, карта связей, решения по фичам, данные | **[REDESIGN-TZ.md](REDESIGN-TZ.md)** | §1 обзор (не prisma), §1.5 карта связей, Раздел 6 решения, §А–§Д заземлённые данные |
| Фильтры, квиз, методология «Подбор» | **[PODBOR-DESIGN.md](PODBOR-DESIGN.md)** | 5 проверок, Primary/Secondary/Drop, спека квиза-гибрида |
| Экраны, раскладка, привязка элемент↔поле | **[WIREFRAMES.md](WIREFRAMES.md)** | 5 экранов desktop/mobile + легенда полей + визуальный референс |
| Задачи, порядок фаз, зависимости, DoD | **[BUILD-BACKLOG.md](BUILD-BACKLOG.md)** | Фаза S → WP0…WP11, граф зависимостей, критерии приёмки |
| Что просить у заказчика, контент | **[CUSTOMER-BRIEF.md](CUSTOMER-BRIEF.md)** + **[CONTENT-CHECKLIST.md](CONTENT-CHECKLIST.md)** | что делаем/почему + что предоставить + вопросы |

**Правило ссылок:** где тема описана НЕ в своём каноническом доке — стоит явная ссылка «каноническое — `<док>` §X»,
и текст там намеренно не дублируется. Видишь такую ссылку при реализации — иди туда, там полная и точная версия.
