# ТЗ: редизайн сценария «Готовые проекты» и «Построенные объекты»

Область: `apps/ncottage-www` (витрина), `apps/ncottage-admin` (CMS), `apps/ncottage-api` +
`packages/shared` (модель). Ветка `feat/ncottage-cms`.

> **v2:** разделы 1–5 дополнены заземлёнными данными из харвеста 594 реальных страниц
> конкурентов/legacy — см. **«Приложение v2»** в конце (реальные числа, структура комплектаций,
> таксономия фильтров, и **коррекции v1** — §Д). При расхождении приоритетна v2.

## 0. Цели и метрика

1. **Конверсия — приоритет №1.** Текущий legacy не приносит лидов; новый сайт по этому
   сценарию слабее и конкурентов (gwd.ru, aps-dsk.ru), и собственного legacy. Цель —
   максимум лидов и возможность их **замерить** (аналитики сейчас нет вовсе).
2. **Сущности на уровне конкурентов.** «Готовый проект» и «Построенный объект» —
   полноценные, богатые карточки с галереями, ценой под ключ, планировками, связями.
3. **CMS для обычного человека** без навыков программирования и знания английского:
   картинка грузится перетаскиванием, а не «положи в public»; нет англо-кодов и жаргона.

Метрика успеха: `lead_success` (цель в Метрике), микроконверсии воронки, доля
мессенджер-обращений. Базлайн — 0 (нечем мерить), первый шаг — включить аналитику.

## 3. CMS для обычного человека

### 3.1 Принципы
1. **Ни одного технического термина** в интерфейсе: `slug`→«Адрес страницы (латиницей)»,
   англо-коды (`sip`,`hi-tech`,`permanent`)→русские подписи через лейбл-мапы, `order`→«Место
   в списке», `og:image`→«Картинка для соцсетей». Технические имена полей (`sourceTitle`,
   `eyebrow`, `seoContent.*`) скрыть.
2. **Нигде не вписывать URL/путь/код руками.** Картинка — только из медиатеки или
   перетаскиванием; выбор из набора — выпадающий список с русскими подписями.
3. **Система подставляет всё вычислимое:** транслит slug вживую, «место в списке» — в конец,
   ширина/высота/обложка — из файла. Руками — только смысловые поля.
4. **Ошибки — по-русски, до сохранения,** рядом с полем; скролл к первому битому + сводка
   «Проверьте N полей». Никаких сырых английских ошибок бэка в исчезающем toast.
5. **Ничего не теряется молча:** `useUnsavedGuard` во всех формах, «Отмена» — с подтверждением.
6. **Подсказка под каждым нетривиальным полем** с примером и куда это попадёт на сайте.
7. **Всегда виден результат:** превью картинки, живой предпросмотр адреса, понятные пустые состояния.
8. **Единообразие:** картинка/список/координаты редактируются одинаково во всех формах.

### 3.2 Загрузка медиа (P0)
Механизм уже готов и корректен: `MediaField/GalleryField → MediaPicker/UploadDropzone →
uploadMediaAction → POST /media → MediaService.upload → MinIO`. Требуется:
1. Заменить **все** сырые TextField-URL для картинок на `MediaField/GalleryField`:
   built-objects image, reviews image, services image, service-scenarios plan.image,
   content/seo og:image, projects floorPlans[].image. Ни одного поля-строки для картинки.
2. **Drag-n-drop на месте:** файл кидается прямо в поле сущности → грузится в MinIO → превью.
   `UploadDropzone` встроить в `MediaField` как основной путь, «Выбрать из медиатеки» — вторая кнопка.
3. **Никаких /public и хотлинков.** Схему `project.image = z.string().min(1)` заменить
   валидатором «только url нашего хранилища» (нельзя сохранить «абвгд» или битый путь).
4. **Миграция legacy-URL** (одноразовый идемпотентный скрипт): built-objects.json и reviews.json
   хотлинкают `ncottage.ru/app/uploads/*`, projects/services — `/public`. Скачать → залить через
   MediaService → переписать поле на наш url. После — в БД нет внешних/`public` ссылок.
5. Первое фото галереи — обложка (drag-сортировка ✓). Размеры не спрашивать.
6. При недоступной картинке — явное «Файл не найден».

## 4. Конверсионный движок (приоритет №1)

Каркас частично есть (`useLeadForm`, `ProjectCalculator`, `FloatingContact`, `CallbackModal`,
`Promo`, `Setting`), но: аналитики нет вовсе; квиз отсутствует; трасты захардкожены в JSX;
